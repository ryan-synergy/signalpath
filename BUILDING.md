# Building SignalPath from the ground up

This document is the reconstruction recipe: the order things were built in, the architectural decisions that made it work, and the lessons that were paid for in debugging time. If the repo vanished tomorrow, a competent developer (or AI agent) following this guide would arrive at substantially the same app.

---

## 0. Philosophy — decide this before writing any code

1. **The engine is headless.** Every stage — load, validate, advise, place, route, render — is a pure function: data in, data (or an SVG string) out. No DOM access, no globals, no state. The UI is a disposable shell around it.
2. **No build step, no dependencies.** Plain ES modules served statically. The whole app deploys by copying files to a GitHub Pages repo. This constraint is load-bearing: it keeps the dev loop instant and the app runnable anywhere.
3. **Tests are a browser page.** `tests.html` imports the engine, runs every assertion on load, and prints pass/fail. No test framework, no Node. The bar for every change is *all tests green*, and behavior changes ship with new assertions.
4. **Measure before keeping.** Routing "improvements" are judged by measured hop counts on fixed fixtures, never by intuition. Several plausible ideas were rejected because the numbers got worse (see §9).
5. **Catalog honesty.** A device spec is `verified: true` only when it traces to a manufacturer datasheet or manual. Placeholders are explicitly `verified: false` and hunted down later. An authored guess that turns out wrong poisons the advisor.

## 1. The data model

A **job** is JSON:

```
{
  job: { name, client, pages: {...} },        // metadata + page flags
  house: {
    zones: [ { id, name, scope,               // scope: included | prewire | future
        remote,                                // savant | appletv | josh | factory
        endpoints: [ { id, type, ... } ],      // display | speakers | keypad ...
        localDevices: [ { id, type, ... } ] } ]// at-display gear: ATV pucks, encoders, Sonos amps
  },
  solutions: [ {
    id, name,
    devices: [ { id, type, model, catalogRef, zones: [...] } ],  // rack gear
    connections: [ { from, to, signal, count } ],                // edges by id
    overrides: { zones: {id: patch}, endpoints: {id: patch} }    // per-solution sparse patches
  } ],
  catalogSnapshot: {...}                       // per-job catalog lockfile, written on save
}
```

Key decisions:

- **Ids are stable and House-owned.** Endpoint/zone ids never change on re-import, so connections and overrides survive a merge. Device ids are namespaced *per solution* (duplicating a solution must not trigger duplicate-id errors).
- **Endpoints belong to the house; devices belong to a solution.** The house is what the home physically is; each solution is one bid's worth of rack gear and wiring against that same house.
- **Per-solution overrides are sparse patches**, not copies. `effectiveHouse(house, sol)` / `effectiveJob(job, solIndex)` apply them; no override means the same object reference passes through (cheap + testable). Patches strip `id`, and an override clears its own `confirm` flag. Structural changes (add/remove endpoints) are only allowed at House scope.
- **Signals are a closed set:** `video`, `audio`, `speaker`, `audioReturn`, `network`, plus scope-derived pre-wire styling. Each gets a color (`SIGNAL_COLORS`) and a grayscale dash pattern (`SIGNAL_DASHES` — video solid, audio `9 4`, return `12 4 2.5 4`, network dotted `2 4`).

## 2. The engine pipeline (`app/engine.js`)

Build these stages in order; each is independently testable.

### 2.1 `loadJob(job)` → normalized job + `indexJob` → `ix`
Normalize defaults, build id→object indexes (`zonesById`, `endpointsById`, `devicesById`, locals), resolve the active solution. Everything downstream takes `(s, ix)` and never searches arrays.

### 2.2 `validate(job, ix)` → errors/warnings
Referential integrity (dangling connection ends, duplicate ids *within a solution namespace*), scope sanity, confirm-flag reminders, readability ceiling (warn past ~`READABILITY_ZONE_CEILING` zones/sheet), orphan endpoints. Nuances learned the hard way:
- A display with an at-display local **source** (Apple TV puck in the same tile) counts as fed — no wire required, no orphan warning. The user explicitly does not want an intra-tile wire drawn.
- A local return encoder with a return input but no backhaul edge to the rack gets a `return-no-backhaul` warning.
- Stale overrides (patching ids that no longer exist) are warnings, not errors.
- **Every per-solution finding carries `solution: sol.id`** (same contract as the advisor). The editor validates the *active* solution's effective house, so a sibling solution's scope checks read the wrong overrides; the UI filters findings to the active solution. Duplicate device ids are detected by walking the raw arrays — the index maps have already collapsed duplicates, so checking their keys can never find one.
- A note with no `near` is a legitimate general sheet note; only a note naming a zone that no longer exists is flagged.

### 2.3 `advise(job, ix, catalog)` → capacity + licensing + notes
The advisor is where the catalog earns its keep. Per solution (every entry carries `solution: sol.id` so the UI can filter to the active one):
- **Port budgets:** amp channels vs speaker loads; analog inputs vs *trunk runs* (see §5); module analog outputs; digital return inputs (`audioReturn` edges vs `optical + coax + digitalCombo + earc` counts).
- **Licensing tiers:** host/processor picks driven by zone/device/room counts against per-platform rule tables (Savant, Josh, Control4).
- **Notes from catalog flags:** `avb` → "needs an Avnu-certified AVB switch" (Savant sells none — silent failure gotcha); `sonos` → LAN-transport note; endpoint feeding a Sonos line-in source → lip-sync note (≥75 ms group buffering).

### 2.4 `place(job, ix, opts)` → geometry
Canonical 11×17 sheet (`SHEET` constants). Rack occupies the left/center: **three columns** — A (sources), B (switching/matrix), C (amps). Zone cards fill the right/bottom.

The one placement rule that took a redline to learn: **amps bottom-anchor to the rack bottom** and **AVB/switching gear bottom-anchors in column A** (sources dress the top of the rack, network infrastructure lives low — both are the same two-phase deferred-tile pattern) (col C stacks upward from the bottom edge, two-phase: lay out A/B first to find the rack height, then position C from the bottom), and **the audio/zone band bottom-aligns with the rack bottom** (dry-layout the band, then shift it down, wrapping upward). This mirrors real racks and makes speaker-wire routing dramatically cleaner.

Zone cards carry their glyphs' relative geometry: display rect, speaker group, stacked `locals` pucks (staggered +26 px per pair), remote corner pill (top-right, user-picked). `place` copies `zone.remote` through. **Audio-only cards are `compact`**: content-driven size (tighter padding, 13px title, width floors at the name plus the remote pill), growing back the moment a display or puck moves in. Compact broke a hidden invariant: uniform card widths were what kept the vertical escape gutters between columns clear, so cluster and audio-band rows now advance on a **column grid** (cell = the cluster's widest card) instead of each card's own width — cards stay small, gutters stay routable.

### 2.5 `route(job, ix, placed, opts)` → polylines + hops
The router is the hardest 40% of the project. See §4.

### 2.6 `render(job, ix, placed, routed, opts)` → SVG string
One big template: frame + title block (text wordmark; logo upload is a future feature), **keynote annotations** (a zone caveat draws as a circled number on its card, with the full sentence in the legend's NOTES block — never as free-floating canvas text), rack tiles with **faceplate glyphs** (AVR = knob ring + display slot; video matrix = 3×3 dot grid; Apple TV = badge; cable box = channel readout; turntable = platter + tonearm; audio input/output modules wear mirrored jack fields — input cluster left with an inward arrow, output cluster right flowing out, matching where the wires attach), zone cards, wires with per-signal color/dash, crossing hop arcs, trunk bus ticks (`×N` at the longest segment's midpoint, paint-order halo), channel strips, dynamic legend (only signals actually present; dashed samples in grayscale mode), **color by kind** (`KIND_STYLE` + `deviceKind` in `app/kinds.js`, shared with the rack elevation so a receiver is purple on both pages: a dark tint and a 5 px left edge per kind of box, keyed to the wire colors; in grayscale the edge is a white pattern echoing the wire dashes; the legend's equipment key lists only kinds in the rack, and its height feeds the fit scale).

Render also bakes the **interactivity contract** (§7): every wire gets a 12 px transparent `path.wirehit` twin with `data-from/to/signal`; every zone card is wrapped in `g.zcard[data-zone]` *with a transparent fill hit-rect* (an unfilled SVG shape only hit-tests its stroke!); every device tile is `g.devtile[data-device]`. The engine stays headless — it just emits attributes; the UI wires the click handlers.

`opts` worth having from day one: `hideSignals` (view-level filter through place+route; legend adjusts; validation unaffected), `grayscale`, `company` (title block), `rawJob` (see §6).

## 3. The UI shell (`index.html`)

Single file, no framework. Dark top bar: jobs dropdown (+ shipped sample fixtures), solution switcher with duplicate-as-new, stage selector, rules chip, hide-network / harness / B/W checkboxes (harness is per-job: `job.job.harnessStyle`), Import/Export/Print. Left panel: collapsible ZONES / GEAR / JOB / SETTINGS tabs. Right: the SVG canvas.

**The side panel (v2, 2026-09-27).** It grew by accretion into a database editor (a 21-row wire list, 15-field zone forms, advisor messages far from their cause); the rebuild is organized the way a tech thinks — rooms and boxes. *Zone rows* are summaries first: `statusMark` (✓ / ! / grey) from `S.findings` (validator + advisor findings routed to the zone by their `ref` — endpoint, adapter or in-zone gear → zone — and to boxes by device id), a what-it-is + what-feeds-it line from `readHookup`, and the first issue inline. Open rows use tap chips for small fixed choices (`chips()`; a chip calls the same handler as its old `<select>` through the `ZH` registry with a `{value, closest}` stand-in, so overrides/solution scope keep working), and push rare fields behind a `<details class="more">` whose open state is kept in `S.openRows` (`more:<id>`). *Box rows* are back panels: inbound/outbound connections as `connRowHTML` rows (keyed `conn:<i>@<context>` because the same wire shows under both boxes it joins and in JOB's list), jack counts from `portCaps` — preferring the advisor's `io` counts (`S.ioByDev`), since one trunk row can carry six channels — and add-connection buttons whose guess never lands an output on a source. *JOB → All connections* keeps the full list with a client-side search. `openConn` sends a tapped wire to its home (the box it leaves, else the box it enters, else JOB); `focusRows` makes the tapped thing the one open row. CSS gotcha found on the way: `.row.open .fields` opened every *nested* row too — row rules are child-only (`> .fields`). The panel width is a per-browser preference (`#grip`, localStorage), dropped while collapsed so the collapsed rule wins.

**Commands and AI (`app/commands.js`, `app/ai.js`).** One vocabulary (`OPS`: add_zones, set_zone, delete_zone, hookup, connect, disconnect, add_device, set_device, delete_device, set_job, add_revision) serves three callers: typed phrases, pasted command lists, and the AI. Design rules that made it safe: (1) *the AI never edits the job file* — it can only propose commands; (2) `planCommands` runs them on a `structuredClone`, each step atomically (a failing step is rolled back whole, later steps still run — re-read the solution after a rollback, the arrays are replaced), and reports every step in words; (3) the caller previews, then applies the planned copy with an undo snapshot (`pushUndo`, per job); (4) commands go through the editor's own functions (hookup.js, quickadd.js), so its rules hold. Names resolve fuzzily but refuse to guess on ties ("which receiver — X or Y?"); "amp 2", "<zone> tv", bare zones disambiguated by the other end. Typed phrases (`parseCommandText`) return null for anything that isn't a command, so the quick-add box falls back to new zones — but a phrase naming an existing zone edits it (typing "patio 75" must not create a second Patio). The built-in AI uses tool use (`propose_changes`, forced), then feeds the validator's verdict back as a `tool_result` and asks for the complete corrected list (≤2 corrections). Keys: the person's own key (localStorage only, direct browser access header) or a proxy (`proxy/worker.js`: origin allowlist + access code + model allowlist + max_tokens cap; the key stays in Cloudflare). A static site can't hold a shared key — anything in the page is public. Tests stub `fetch` with a fake Claude that errs once, proving the correction loop without spending credit.

**Rack starting points (`app/starters.js`).** `STARTERS` = gear (catalog refs, named by `productName`) + in-rack patching (+ encoder companions for MXNet); `applyStarter` fills a blank job; the quick-add placeholder suggests the matching zones line. `autoHookup` grew to finish zones the way a tech would — stereo-type sets onto the next amp zone with room, surround onto a free (or new) receiver fed from the matrix — found by a test that builds each starter + its suggested zones and demands zero errors and clean routing.

**Zone hookup (`app/hookup.js`).** Connections are edge-centric, but people think zone-first: "the receiver feeds this TV and these speakers." The HOOKUP section in each zone row is a zone-centric *view* over the same connection list — `readHookup` derives {video from + run, speakers from + outputs, audio return} from the edges (a companion in front of the TV means the run is that adapter), and `setVideo` / `setSpeakers` / `setReturn` rewrite just those edges. Rules that matter: an adapter the new choice doesn't reuse is removed with every wire into or out of it (no dangling baluns); switching run type reuses a matching adapter; an AV-over-IP source defaults to an MXNet decoder, other rack sources to an HDBaseT balun, in-zone gear to direct; moving speakers to an amp claims the next free output block (`nextFreeOutputs`), re-picking the same amp keeps its outputs; new edges inherit the zone's scope so pre-wire zones don't trip scope-mismatch. Quick-add `avr` reuses a receiver only if it isn't already driving another zone's speakers, else adds "AV receiver — <zone>" (tiles split placeholder names at the dash so the type stays whole). **TV audio back** is one choice over two facts: eARC is a flag (`earc: true`) on the video edge *leaving the receiver* (receiver→balun or receiver→TV) — it's a property of that HDMI, not a wire, so it draws nothing and adds no schedule run; optical is a real `audioReturn` edge (optionally `backup: true`). `readHookup` folds them into `audioBack` = earc | earc+optical | optical | none; `setAudioBack` writes both. eARC defaults on when a receiver feeds the TV, is carried across run changes, never exists on a non-receiver source, and an existing optical-only choice isn't overridden. Field reality encoded: eARC through an HDBaseT balun / MXNet decoder raises an `earc-extender` advisor note (many extenders pass ARC only) unless the optical backup is present. User's practice: eARC normally, optical backup rarely, "in case ARC is unreliable". No engine change was needed — every hookup shape already validated and routed; the gap was purely that the only way in was hand-building four connection rows.

**Words on screen, ids in the file — one vocabulary.** Stored values stay machine words (`videoMatrix`, `audioReturn`, `surround-5.1`, node ids) because the engine, fixtures, importers and tests read them. Every word a person reads for them comes from `app/names.js`: `TYPE_NAME`, `ADAPTER` (full name + sheet chip tag: HDBaseT balun/BALUN, MXNet encoder/ENC, MXNet decoder/DEC), `SIGNAL_NAME` (+ `SIGNAL_SHORT` for the legend, which must be the first words of the long names), `STATUS_NAME`, `SCOPE_NAME`, `SPEAKER_SETUP`, `REMOTE_NAME`, `PLATFORM_NAME`, and `describeNode(job, sol, id)` → `{group, label, short, kind}` for any connection end ("Anthem MRX-540 (AV receiver)", "Family Room TV (75\")", "HDBaseT balun at Family Room TV", "Apple TV in Patio"). The editor, sheet (chip tags, TV captions, legend), print pages, validator/placer messages, quick-add chips and import notes all import it. "Zone" is the place word (tabs, channel map and amp budgets already said it). Validator and placer findings are written for people and carry the raw id as `ref` for code and tests; the advisor turns router wire ids into names with `humanizeWireIds`. A test breaks the residence every way the validator knows and asserts no message, advisor line, print page or sheet text contains a raw id — it caught two real leaks on its first run (the channel map's receiver summary printed a decoder's id). Product names: `productName(c)` = brand + model with a trailing part-number parenthetical moved to `productSku` (descriptive ones like "(Gen 2)" stay; a model that already starts with the brand isn't doubled). Picking a catalog product sets the device's `model` to it — the old rule only renamed "New Device", so a box could be linked to "Anthem MRX 540 8K" while the sheet said "Anthem MRX-540". GEAR flags drift and offers per-row / all-at-once fixes (existing jobs are never renamed silently). Tiles: `fitText` squeezes a label with `textLength` past its width (model line stays clear of the status LED), and `tileName` keeps the brand whole using the job's locked catalog entry or `MULTIWORD_BRANDS`. Why: the user found an AVR→TV hookup "random" when the pickers showed ids; editors are for people.

The core loop is brutally simple:

```js
function refresh() {
  autoLinkCatalog(S.job, effectiveCatalog());          // self-heal catalogRefs
  const v = loadJob(effectiveJob(S.job, S.sol));       // apply active solution's overrides
  // validate → advise → place → route → render → inject SVG → advisor strip
}
```

Every field edit mutates `S.job` and calls `refresh()`. Autosave debounces 400 ms into IndexedDB. Settings (company block, licensing tables, editable catalog) live in an IDB `__settings` record; on boot, *newly shipped* catalog entries merge in but changed fields never overwrite user edits (a "reset to shipped" button exists for that — remember this when shipping catalog corrections).

When 2+ solutions exist, the ZONES panel shows an "EDITS APPLY TO: House / *solution* only" scope bar; overridden fields get an orange outline and an × revert affordance.

## 4. The router (the hard part)

A structured **channel router**, not a maze solver. Wires travel in registered lanes (`usedH`/`usedV` maps per corridor, sub-lanes for `c`/`a1`/`a2`/`net` classes) so parallel runs space evenly and never overlap. Passes, in order:

1. **Stubs** — intra-card wires: chip→endpoint, local source→display, display→local encoder (in-card orange return stub at `x = cx + 14`), and TV→soundbar (an endpoint→endpoint same-zone connector: down from display bottom, across, up into the speaker group). Stubs never enter the channel system.
2. **Fan-out plans** — per source device, sort targets farthest-first so nested risers don't cross; west and east targets are separate fan-outs.
3. **Rigid runs** — rack-to-rack. When the B/C column gap's center lanes starve, use edge channels (`gap[1]-6`, `gap[0]+6`). Same-column stacked neighbors get a tight **staple** (out the edge facing the target, short channel beside the tiles, in the target's *right* edge) — the over-the-top column wrap is the fallback, chosen only when it measurably crosses less. A-column feeds may also **wrap the west margin** (out the left edge, down the outside, in at port height), taken only when it saves ≥2 crossings over the gap descent. Candidates that lose a cost comparison must only *peek* at ports — a considered-but-rejected candidate that claims a real port can eat both lanes of a 22px tile and wall off a later arrival.
4. **West feeds / east feeds / returns last.** East feeds from bottom-anchored amps use the **dive template**: drop below the audio band via an allocated riser in `[ampRight, eastBandMinX]`, advancing **westward** so the nearest target takes the eastmost riser and farther siblings dive wider and deeper — the strips nest instead of walling each other off. Returns (pass 4c) route after everything, scored by `crossings*100 + pathCongestion` (±30 px neighbor density — measured neutral on current fixtures, kept as insurance), with jog-prefix candidates (allocated gutter descent when the straight drop would pierce a stacked card) and a second scan band beneath the dive-strip territory (`rackBottom+24 … +560`; the first ~340 px belong to dive strips).
**Guided rerouting:** users can override the router's taste per wire, but never its legality. A connection may carry `routeHint` — topological, not geometric: `{ch: "ab"|"west"|"staple"|"wrap", between: [devIdA, devIdB]}` for returns and rack runs; zone feeds take `{ch: "col"|"gutter"}` (west feeds: riser beside the rack vs. past the room band), `{land: "top"|"bottom"}` (east feeds: which card edge), and `{bundle: true|false}` (ride the harness / own run; a `ch` or `land` pin implies own run). The first feed of a group routes first and *is* the trunk, so it never offers "ride". The router honors a hint by constraining its candidate search (channel range pinned, lane band pinned to the strip between two named devices); if the pinned route can't exist it warns `hint-unroutable` and falls back to auto — a hint can never unroute a wire, and the source-exits-right rule outranks hints. `routeAlternates(job, ix, placed, opts, wireId)` re-runs the router under each viable hint and returns the distinct legal paths for the picker UI (ghost previews with live crossing counts). Hints live on the connection object, so they persist, survive `mergeHouse`, and re-route fresh against any future layout. Freeform wire dragging was explicitly rejected: persisted pixel paths go stale on every layout change and fight the deterministic router.

**Route efficiency audit (2026-09-27, `app/route-audit.js`).** The router's guards proved drawings *legal*; nothing measured whether routes were *efficient*. The audit is an independent oracle: per wire, length vs the Manhattan minimum, bends vs the fewest possible for its exit/entry sides, smells (redundant vertices, retraced spikes, <6px hairline jogs), and a search for a simpler route (L / Z / one dog-leg) that leaves and lands the same way, pierces no body, overlaps no wire and crosses no more wires. It ignores lane clearance and corridor reservations, so a flag is a lead — returns are the proof: their "shorter" routes squeeze past rack gear closer than `RT.clear` allows, so they stay. What it found and what changed:
1. **Top-band feeds had one shape and one fallback.** `[port → riser → corridor lane → drop]` in the column channel, else a riser in the gutter *past the east end of the whole top band* — wires ran to the sheet edge and doubled back (worst: a 3,850px run for a 1,930px trip). Now every sensible shape is built — column channel, the right corridor for A/B-column sources, and the direct **L** (out at port height, up at the drop) for rooms east of the rack — and the cheapest wins (`crossings × 100 + length/10`); the gutter is the last resort. A pinned `ch` hint keeps its old exact order.
2. **East feeds took the dive whenever it existed** (below the whole band) even when a riser beside the target reached it at card level; both are built now and the cheaper wins (riser tracks snapshot/restored so the loser leaves no state).
3. **Chips were approached by comparing the source with the card TOP.** A mid-band TV's chip hangs below its card, often below the source port, so every lane went "above" and through the card; wires fell to the below-rack escape. A chip is always approached from below, lanes starting under it.
4. **`tidy()` in `commit`:** repeated/straight-through points dropped, and a <4px jog next to either end removed by sliding that end ≤3px along its port edge (two ports a pixel apart drew a visible notch).
Tried and rejected: scanning between-row lanes from the edge next to the card as well as the customary 26–40px start — better for each wire, but greedy lane-taking starved later wires (residence hops 5→13). Measured on 200 random jobs × 3 seeds: wires with a >200px shorter legal route −43…−48%, hops −4…−5% (stress fixture 308→272), smells −78…−88%, fallbacks down. Tests hold the new level as ceilings (fixtures: no >200px lead, no smells; 60 random jobs: ≤17 leads, ≤1.175× Manhattan, ≤2 smells, ≤5 fallbacks). `app/fuzz-jobs.js` is the shared seeded generator (fuzz + audit + tests draw identical jobs).

**Hops and twists (2026-09-27, from a sheet Ryan flagged).** Two things read as mistakes on a real sheet: (1) *one wide arc* over a bundle — the hop pass bridged a run of same-signal wires with a single half-circle as wide as the bundle (40–60px, taller than any tile label); (2) *two wires wound round each other* — red crossed blue's riser, then blue crossed red's drop, two hops a few px apart, one on blue's corner. The arc itself turned out not to be the complaint: we tried one small bump per crossing (hopR 4, flat merged bridges) and Ryan preferred the **single big arc over a bundle** — the convention he knows — so that stays (hopR 6, one half-circle per bundle). What he disliked was the twist. Fix: **pass 4d, untwist**: for every pair of feeds/returns that cross, try swapping their lane heights, their riser columns (the first vertical after the port stub — stacked sibling ports whose risers are in the wrong order cross each other's stubs), or both; keep the move that cuts the most crossings, only if both new paths are legal (no body, registrable) and no fan-out sibling is crossed. Why swaps and not a re-route: re-routing the pair in the other order let the second wire grab the first one's riser too, making a new crossing — the geometry that was wrong was only the *order* of two lanes or two risers. `routeWestOne` is now a function (it was the loop body) so single feeds can be re-routed. Measured (200 jobs × 3 seeds): pairs crossing twice 994→397 (−60%), total hops −19%, stress fixture 272→192, estate 25→18; stress route time 8→23ms. `route-audit.js` gained `doubleCrossings()` and `cornerHops()`; tests hold fixtures at ≤0/1/17 twists, no corner hops, and no two hops on a segment touching (a bundle gets ONE arc). Harness style no longer always beats plain routing by crossings on small sheets (bundled wires aren't swappable) — it still wins big on dense ones (stress 192→177).

**Bundles move as one (2026-09-30).** A harness member takes its leader's *net*, and the lane registry is keyed by net — so anything that edits a leader must edit its members too. Two passes didn't: **4d** swapped a leader's lane or riser alone (`unreg(net)` dropped the members' registration with it), leaving the members' copied trunk on the old riser, unregistered, and the swap partner then landed exactly there — two sources drawn as one wire (fuzz seed 1, random #12: src0→z11-tv up src2→z3-tv's riser at x=198); and the **4a untwist** ripped up a leader's whole net and re-routed only the leader, so its members vanished from the sheet with no warning (random #33 in harness style: 17 connections, 13 wires). Now 4d carries each move onto the members (`carry()`: the shared prefix takes the leader's new points, the breakout slides with the run it leaves from; the move is dropped if any member would bend diagonally or reverse a leg) and validates leader + members as a unit; the 4a untwist skips a pair whose net carries members. Every classic variant (default, harness, outdoor, reroutes) is now held to the no-shared-lane check the fuzz only applied to trunk mode: 193 flagged jobs → 0 on seeds 1 and 7. Pairs crossing twice on the 60-job corpus 77 → 64 — the old count was partly bought with those illegal overlaps (excluding bundles from 4d outright cost 111).

**Harness bundling (pass 4b′).** Zone feeds that find no lane of their own don't fall back immediately — they queue until every sibling has committed, then ride an already-routed sibling (same source device, same signal) by *taking its net*: the lane registry and the hop pass already treat one net as one conductor, so the shared run is legal by construction. The breakout search walks the sibling's path and tries L- and Z-shaped branches into the target (chip from below; card from below or above), picking fewest crossings, then the shortest breakout — so bundles stay together until they're near their destinations (the electrical-drawing convention the user asked for). Members carry `bundleOf` (root wire id) and `trunkLen`; render draws the shared trunk as a heavier translucent underlay with a ×N bus tick on the root segment carrying the most wires. Only would-be fallbacks bundle, so clean sheets are unchanged. On a 200-job random corpus, fallback wires went 349 → 13 (layouts with any fallback 91 → 8); what remains is mostly lone feeds with no sibling to ride.

**Harness style (by choice).** The same machinery as `bundleOnto(h, proactive)`: with `job.job.harnessStyle` (or `opts.harness`, which wins) the 4a/4b passes try bundling *before* routing a feed alone, for any source with 3+ room runs of that signal (rack patches don't count toward the 3). Proactive bundles only ride other zone feeds, never a rack-to-rack patch; a feed with no legal breakout routes alone as usual. Plan order already routes the farthest target first, so the trunk leader is the one the others branch off. Measured on the corpus: crossings −29%, drawn line length −34%, zero bodies crossed; the stress sample drops 319 → 247 hops. Breakouts may not pass through their own target chip except on the final landing leg (the chip is exempt from `segBlocked` so the wire can land on it — found by fuzzing reroutes, where a trunk above the balun dropped straight through it).

**Return fallback.** Every wire class draws a flagged best-effort path when the corridor is full — returns included. A return that finds no legal lane on any free entry port draws its first sane attempt (never piercing its target) as `return-fallback` with a `route-fallback` warning; before, it vanished from the drawing entirely. The UI surfaces `unrouted`, `route-fallback` and `hint-unroutable` in the advisor so a compromised drawing is never silent.

5. **Hops** — where wires must cross, the later wire bridges with an arc. A relaxation tier turns forced sibling crossings into bridged hops (reported as `route-relaxed`); flyover is the last resort and counts as a failure smell.

**Trunk runs:** a module→amp audio connection is N physical runs, not one line. `trunkCount(conn, s) = max(conn.count, zones the amp feeds)` — derived from downstream speaker edges so the drawing can't understate capacity, while an authored `count` can add spares. Rendered as one line with a `×N` bus tick; the advisor and channel map consume the true count.

**Debugging infrastructure is not optional.** `route({debug:true})` exports registered channel segments; `place-preview.html` draws placement boxes, routed wires, and a congestion heat overlay. The `rdbg` candidate log (why each return candidate was rejected: `blocked:z19` etc.) is what cracked every hard routing bug.

**Regression guards:** hop-ceiling tests per fixture (currently residence 5 / estate 25 / stress 319, zero fallbacks), plus a geometric never-pierce test: no return/backhaul segment other than the final approach may intersect its target tile. That guard exists because of a real bug: the target tile is exempt from `segBlocked` so the final approach can land on its edge, and that exemption silently blessed a lane that crossed the module's *body*, wrapped the west margin, and re-entered from the left — scoring loved it because cheating through the target costs zero crossings. Any routing change that raises a ceiling must justify itself (the 12→14 residence re-baseline was the price of fixing that pierce).

## 5. The catalog (`app/catalog.json`)

Typed I/O per device: `{ inputs: {analog, coax, optical, hdmi, earc, digitalCombo, dante...}, outputs: {...}, ampCh, flags: [...], verified, source }` plus licensing rule tables per platform. ~55 SKUs across Savant (legacy AVB backplane *and* current PAV IP boxes — two distinct architectures), Sonance (incl. Blaze/MKIII), Anthem, AudioControl, AVPro Edge (MXNet + HDMI matrices), Sonos, Dante bridges.

Process that made it trustworthy:
1. Author placeholders honestly (`verified: false`).
2. Cheap-model research agent does distributor/manual sweeps per brand; findings merged with flags added (agents forget flags like `sonos` — the advisor keys on them).
3. Personal PDF pass on whatever stayed unresolved: fetch the actual manuals, read the rear-panel diagrams. This pass overturned *distributor* claims several times (Sonance MKIII "half-populated" myth; MX-1616 phantom digital outs; M6800D analog count).
4. `autoLinkCatalog` self-heals saved jobs: exact normalized model match (+ known-alias map, + 8K/4K suffix tolerance), same-type only, **never fuzzy** (Axion 8 must not link to AC-MX-88), never touches existing refs.

## 6. Print pages (`app/pages.js`)

Pure functions again: `renderChannelMap` (per-device port tables; amp tables gain a Feed column when trunk-fed), `renderTakeoff` + `takeoffCSV` (NEW/OFE rollup, prewire/confirm/licensing boxes, billable remotes via `REMOTE_BOM`; given `opts.catalog` — the packet and the CSV pass it — adapters are named by `companionSku()` in network.js, the same part the PlanQueue export quotes (AVDM vs EV2 encoder, the RNE receiver alone off an AXION), and each Bullet Train run and eARC kit gets its own line; without a catalog the generic adapter names stand), `renderWireSchedule` + `wireRuns` (V/N/R/S numbering, cable totals; skips in-room links — local feeds and returns that terminate at a local/endpoint must not emit phantom home runs), `renderBomCompare` (≤4 solution columns).

**Network & Power (`app/network.js`, `app/power.js`).** Both are pure plans computed inside `advise()` (it already has the catalog; the page renderers don't) and attached as `advise().network` / `advise().power`, so the page, the advisor notes and the AI export read one answer. *Ports:* every edge touching a switch is a port — except Dante subscriptions (`dante: true`), which are box→box streams, not cables. A `danteSwitch` also collects the Dante gear whose links never touch it (AXIS companions, bridges, Dante amps); DANTE-DV2/EV2 companions stay on the MXNet switch (VLAN 99), and their presence adds a trunk row on both switches. *House LAN:* every included TV, every rack box with a jack (`lanPorts`: catalog `lan` wins; splitters/downmixers/turntables have none), in-room gear, and one uplink per AV network (stacked switches of the same kind share one) go on the job's LAN switch — or on a virtual `HOUSE_LAN` stand-in ("House LAN switch (to add)") that the advisor sizes. A control box counts on the LAN even when it's on an AV switch: its control port is a separate jack. Port order: control boxes, rack gear, zone gear by zone order, TVs, uplinks (SFP cages first). *Outlets:* one per rack device (catalog `outlets` for multi-cord), zero when the port plan says a PoE switch powers it — so the two plans must agree on PoE, which is why power takes the network plan as input. Auto-picks use only catalog entries flagged `wattboxPick` (the 800 lineup; 20A 820s need a 20A circuit, so they're never auto-picked). Spare target: 20%, min 2.

**Rack elevation (`app/rack.js`) and circuit load.** `rackPlans()` runs in `advise()` (→ `advise().racks`) beside the port and outlet plans. Build order is a tier per device type (patch 0 · network 1 · control/processing 2 · sources/shelves 3 · amps+AVRs 4 · power 5), sorted stable; the page anchors tiers ≥4 to the rack floor when everything fits. Catalog fields: `rackUnits` (number; `null` = unknown), `desktop: true` (small box → shelf), `halfRack: true` (pairs side by side), `mount: "vertical"` (rear rails, 0U), `outlets` (cords), `powerTypicalW` (1/8 power or the maker's "typical"), `powerMaxW`, `powerIdleW`, `powerNoPoeW` (a PoE switch's own draw). rack.js imports `wireRuns` from pages.js for the Cat6 count while engine imports rack.js — an import cycle that's safe only because every cross-module use happens inside functions, never at module top level; keep it that way. Circuit math lives in power.js: sums prefer typical (else max), switches with `powerNoPoeW` count own draw + their PoE rows' device watts (12.95 W 802.3af ceiling when unpublished), capacity = 0.8 × breaker × 120 V per WattBox.

**Sizing profiles (`catalogFor` in network.js).** A catalog entry with `match` (a case-insensitive name pattern, same `type`) sizes gear the job names but never linked — watts, rack units, shelf, Ethernet. It is deliberately *not* a link: `autoLinkCatalog` and the exports still read `catalogRef` only, so "Cable Box" keeps quoting as provider equipment (`provider: true` also flows through `fromCatalog` when someone does link one). Rack kits are catalog entries with `rackKit: {gen, holds, excludes?}`; rack.js chooses per remaining count the kit with the lowest `ceil(n/holds) × rackUnits`.

**RACK tab / "?" values.** The job can carry its own figures on a rack device (`rackUnits`, `powerTypicalW`, `powerMaxW`, `outlets`) and hardware part numbers (`job.job.rackParts` {rack, patch, vent, shelf}; a rack's own `partNo` wins for the enclosure). `specFor(d, catalog)` = catalog/profile spec with those on top, and every rack/power calculation reads it — so a typed-in value changes the elevation, totals, notes and sheet at once. The tab writes a value only when it differs from the catalog (typing the catalog's own number back clears the override). Unknown = `null`, rendered "?" (never 0). `effectiveCatalog()` merges the job's locked snapshot field-by-field over the live entry, so locked values hold but new fields arrive.

**Top-bar menus.** File / View / Export are `.menu` wrappers (`.mbtn` + `.mlist[hidden]`); the original buttons and checkboxes kept their ids and handlers and simply moved inside, so nothing else changed. One document-level click listener closes menus; a click on a menu *button* item closes after its own onclick has run (target handlers fire before the bubbling listener), a checkbox click doesn't close. The top bar no longer overflows at laptop widths (1,756 → ~1,110 px of content).

**Mid band + tight spacing (2026-09-27).** By-type grouping moves TV-only zones (`tvRank` 2) out of the top band into a `band: "mid"` block laid out on its own column grid right of the rack and set on top of the audio band (gap = `rowGapFor` its last row, so chips + feed lanes fit); it only exists when the job has rack gear and the top band keeps TV+speaker rooms. The router treats "mid" as east (`regionOf` → "audio"). Bands use `gridCell()` = the 75th-percentile card width with wide cards spanning whole cells. Spacing `cardGapX 20 / rowGapY 24` was picked by measuring hop counts across 30/24/20 × 30/24 (24px gaps oddly cost the residence 2 hops; 20/24 held 5 and cut stress 319→308). The mid band exposed a return bug: `routeReturn` could take a lane above its own card's bottom (hint bands between rack devices, or the below-rack fallback) and climb back through the card — lanes above `laneLo` are now rejected.

**The BOM-compare trap:** editor callers pass the *active-solution-effective* job. Columns must derive each solution from `opts.rawJob`, or the active solution's overrides silently leak into every column. This is guarded by a test; keep it.

Print = new window, `@page 17in 11in landscape`, one SVG per page, `print()`. Page flags live in `job.job.pages` (channel map, equipment and network on by default; wire schedule and BOM compare opt-in); BOM compare only counts when 2+ solutions exist, and the Network & Power page renders nothing when the job has no switches and no rack.

**Catalog lock.** `lockCatalog(job, catalog)` (run on every save) freezes each used entry the first time it's saved and never overwrites it; `catalogDrift()` lists used entries whose live catalog data differs (surfaced in the advisor and the JOB tab); `refreshCatalogLock()` pulls current specs in on the user's say-so. The editor's `effectiveCatalog()` already lets snapshot entries win — before this, every autosave rebuilt the snapshot from the live catalog, so nothing actually stayed frozen.

**Pagination.** Nothing may draw below y=900 (footnote at 920, footer bar at 940). Each renderer is a `…Pages()` function returning one SVG body per physical sheet: tables split row-wise via `tableFit()` under a "(cont.)" heading (the channel map fills its two columns shortest-first, then opens a new sheet; the takeoff's left and right columns paginate independently; the wire schedule and BOM compare repeat their header row). `renderExtraPages` runs a counting pass first, then renders with true labels, and `sheetTotal()` gives the main drawing its real "1 of N". The single-page `render…()` exports remain as first-sheet wrappers for callers and tests. The 25-zone stress job grew from 4 sheets (with rows running off the paper) to 7.

## 7. Interactivity, quick-add, importers

- **Wire tracing:** canvas click delegation; `elementsFromPoint` cycles overlapping wires in a bundle; selection dims everything else (`.wiresel`), glows both endpoints, shows a tooltip with human names. Tap zone card → open + flash its ZONES row; tap device tile → GEAR. The wire tooltip links both ways: *Edit connection* (`openConn`: resolves the wire to its connection index by from→to + signal, makes it the only open connection row, scrolls after the panel's open transition — scrolling a panel that's still animating open overshoots) and *Zone hookup* (`wireZone`: the zone at the far end, through any adapter, or the near end for a return). Opening a `conn:` row selects its wire; editing an end re-keys `selWire` so the highlight follows the renamed wire. (Testing gotcha: dispatch synthetic clicks on the *target element* with `bubbles: true`, not on the canvas — `e.target` is wrong otherwise.)
- **Quick-add (`app/quickadd.js`):** pure parser for `"family room 5.1 75 sony matrix"` → zone. Spoken-form normalization ("five point one" → 5.1), brand list, scope/OFE/local/matrix/remote tokens, landscape N, projector N, comma/"then" batching. UI adds live preview chips + Web Speech dictation.
- **Importers (`app/importers.js`):** `sniff` by key shape, adapters for SiteWalk surveys and Blueprinted (Savant config) exports, and `mergeHouse` for re-import: match zones by name, keep endpoint ids stable so connections/overrides survive, never delete unmatched.
- **Walk → drawing (`drawFromWalk`) + the AVWalk link.** `importSiteWalk` keeps a per-zone `walk` record (video feed, audio feed, passive bar, shared audio-zone label) on the result — never in the job — and `drawFromWalk(res, catalog)` spends it through `hookup.js` (`setVideo`/`setSpeakers`), so the draft is ordinary gear the editor already understands. Rules that came out of testing against AVWalk's golden surveys: the *room* is the zone (a walk `zoneName` like "Main Level" is an audio grouping → note + own outputs on the same amp; paralleling two rooms on one output is a validator error, correctly); receivers without a matrix feed get sources only when there's exactly one (two can't share a source without a splitter — say so instead); powered soundbars hang off the TV (`audioReturn`); a TV the walk left with no feed stays flagged. The link format is `#avwalk=` + base64url(raw DEFLATE(JSON)) — Apple's `.zlib` *is* raw DEFLATE, the browser reads it with `DecompressionStream("deflate-raw")`; a Swift-made link is decoded in the browser as the cross-check (AVWalk `Core/Sources/SiteWalkCore/Handoff.swift` + `testSignalPathHandoff`).
- **The import door is a trust boundary.** `importAny` runs `stripUnsafe` (recursively deletes `__proto__`/`constructor`/`prototype` keys — JSON.parse happily creates them as own properties) and, for native files, `assertJobShape`: reject anything missing its identity skeleton (schema version, `job` block, `house.zones`, at least one solution, ids on every zone/endpoint), but *normalize* missing lists to empty. Reject-vs-normalize matters: a malformed file must never replace a working job and then get autosaved over it, while a hand-edited file missing an optional array should just work.

## 8. Dev + deploy loop

- **Dev:** edit source → rsync to a temp preview dir → static server with `Cache-Control: no-store` (module caching *will* burn you otherwise; cache-bust dynamic imports with `?v=Date.now()` in tests) → verify in browser → run `tests.html`.
- **Deploy:** `./deploy.sh "message"` — copies `index.html` + `app/*` + fixtures + docs into the git repo, stamps the build, commits, pushes; GitHub Pages serves from main root. Poll the live URL for a marker string to confirm (~30–45 s).
- **Build stamp.** GitHub Pages sends `Cache-Control: max-age=600`, so for ten minutes after a deploy a browser can run a new `index.html` against cached old modules (or the reverse) — a missing export and a blank app. `index.html` carries an import map listing every `app/*.js` as `./app/x.js?v=dev`; module-to-module imports resolve through the same map, so one stamp versions the whole graph (plus `catalog.json?v=`). `deploy.sh` rewrites `v=dev` to the UTC time in the deployed copy only. **A new module file must be added to the import map** or it will be fetched unstamped. Backstop: a classic script in `<head>` watches for script errors until the module sets `window.__spBooted`; a load failure shows *"SignalPath was just updated — Reload"* (Chrome/Safari/Firefox wordings for a missing export are all matched) and anything else shows *"didn't start"* with the message — never a blank page.

## 9. Lessons (the expensive ones)

1. **Extract layout rules from the user's real documents.** "Amps go bottom-right" was visible in their example schematics all along; under-extracting it cost a full placer/router surgery later.
2. **Rejected-by-measurement is a result worth keeping.** Global river-ordered west lanes (hops 21→27 — stub interference breaks the theory) and west-lane cost sampling (marginal, broke a return) are documented failures so they don't get re-tried.
3. **When routing fails, instrument — don't guess.** Every hard bug fell to logging why each candidate was rejected, not to staring at the picture.
4. **SVG hit-testing:** unfilled shapes only hit their stroke. Bake transparent hit twins/rects at render time.
5. **Distributor listings lie; manuals don't.** Three catalog "facts" from retailer pages were overturned by rear-panel diagrams.
6. **DOM `outerHTML` doesn't entity-encode quotes in text nodes** — regex tests like `/85"/` will match `x="475"`. Use DOM queries or precise matchers in tests.
7. **Draw what installers mean, not what graphs imply:** an Apple TV puck inside a room tile *is* the connection — drawing a wire there is noise. Model the exemption, not the edge.
8. **Sparse overrides beat solution copies.** Copies fork; patches keyed by stable ids survive re-imports and diff cleanly.
9. **Hardening checklist for a static app** (all guarded by tests): one *full* `esc()` everywhere — `&<>"` — because a quote-less escaper is safe in text nodes but not in `value="…"` attributes; escape even "internal" sinks like the print window `<title>` and error messages (they carry user strings); CSV cells starting with `=+-@` get an apostrophe prefix (spreadsheet formula injection); every IndexedDB request promise must reject on `onerror` or a failed save hangs silently — and the DB open itself needs a fallback (in-memory Map + a one-time "export your work" warning) so private-browsing mode doesn't kill boot; stored settings merge defensively (a partial `__settings` record must not brick startup); external URLs (kit manifest) pass a scheme allowlist before becoming `href`s.
10. **Crash tests can't see geometry bugs.** The first fuzz pass (crashes, malformed SVG, `undefined`) reported 1,100 random jobs clean — and missed that amp escape routes cut through their own amp in 153 of 200 jobs, plus in the shipped estate and stress samples. Adding *geometric invariants* (no segment crosses any device, chip or card body; hop arcs fit their segment; no vanished wires) found them immediately. Assert what the drawing must look like, not just that code ran.
11. **Any exemption list is a place bugs hide.** The router exempts a wire's own source and target from collision checks so it can land on their edges — and three separate bugs hid behind that: the return piercing its target, the col-C escape running back through its own amp, and a stub poking into a card. Exemptions must be per-segment (final approach only), with a separate check for the rest.
12. **Peek-don't-claim, everywhere.** The second "loser claims a port" instance: the return router claimed its entry port before searching and never retried, so a blocked port made the wire vanish. Candidates peek; only the winner claims; a planned booking the winner doesn't use gets released.
13. **Warn on the outcome, not per attempt.** Hint warnings fired inside a per-port retry loop — duplicated, and false-positive on hints that ultimately succeeded.
14. **Deferred saves belong to the object that armed them.** A 400 ms autosave timer read the *current* job when it fired, so deleting a job right after an edit wrote it back, and switching jobs dropped the last edit. Flush pending saves before switching; cancel them before deleting.
15. **Escape every interpolation, including ids and numbers.** Text was escaped but ids in `data-*` attributes and `querySelector` strings were not — a crafted import could run script. Fixed three ways: a strict id charset at the import door, `esc()` on every attribute, `CSS.escape()` on every selector.
16. **Paper has edges.** Every print table grew without bound; a 25-zone job ran rows off the sheet and nobody saw it because the SVG still rendered. Any fixed-size output needs an overflow rule and a test that checks it.
17. **Check the channel table before blaming density.** 165 of 349 "crowding" fallbacks were a one-line omission: the riser-channel choice only knew columns B and C, so column-A sources were sent across the whole rack to the far corridor. Small jobs failing is the tell — crowding doesn't explain a 3-TV house.
18. **Borrow the domain's own answer to density.** Electrical drawings solved crowded corridors long ago with harnesses. Modeled as "a failing wire joins a sibling's net", it needed no new registry rules, and it removed 96% of the remaining fallbacks.
19. **An exemption is scoped to where it's needed.** "Skip the target chip" existed so a wire could *land* on it, but it applied to every segment. Exemptions for the endpoint belong on the last leg only — the same bug returns had (`hitsTarget`), found again in bundling.
20. **One thing, one name — enforced.** The same balun was "HDBaseT receiver" in the editor, "Balun" on the channel map and "HDBaseT Balun" in the takeoff. Label tables scattered per file drift; one vocabulary module plus a test that fails on raw ids keeps it honest.
21. **Let the AI propose, never write.** Giving a model the job file would make every hallucination a corrupted job. Giving it the same small command set the UI uses — run on a copy, checked by the validator, previewed, undoable — turns its mistakes into ✗ lines in a preview it can read and fix.

22. **Bridge apps through the fragment, not a server.** Two static apps on different devices can hand off a whole survey with nothing in between: compress it into the URL `#fragment` (never sent over the wire), open or AirDrop the link, and strip it with `history.replaceState` on arrival so it doesn't sit in the address bar. Build the link at tap time; verify the pair by decoding a link the *other* side made.

23. **A seed catalog needs an update path, not just an add path.** "New entries join, user edits win" meant every spec correction (Beam Ultra, the whole I/O audit) silently never reached a browser that had opened the app once. Fix: remember what was shipped when each entry was taken (`catalogBase`, stable-stringified); an entry still equal to it is unedited and follows the new shipped version; an edited one is kept and listed with an Update button. Legacy entries with no base can't be told from edits — list them, never overwrite.
24. **One port vocabulary, enforced by a test.** The advisor only reads the keys it knows. `lineOut`, `loopOut`, `balancedAnalog`, `eArc`, `ports` all crept in from different research rounds and were silently uncounted. Canonical keys — in: hdmi, earc, analog, coax, optical, digitalCombo, dante; out: hdmi, analog, sub, coax, optical, dante, gbe, gbe25, sfpPlus — with a test that fails on anything else. Details (balanced, loop-through, via-adapter) go in flags/notes, not new keys. `analog` = stereo pairs; amp `zones` = stereo zones (8 channels = 4 zones — the Sonance line had been counted in channels, doubling its capacity).

25. **Model new distribution as the old shapes, then fix the router where the shape is new.** Dante needed no new signal type: TV-side encoders are companions (chips) like baluns/decoders (`axis`, `axis16`, `dec`+`dante`), and a subscription is an `audio` edge with `dante:true` (dashed wire, legend row, Cat6-to-switch run). The drawing broke only where the geometry was genuinely new — TV→own-chip (now a stub), zone chip→rack (now routed as a return that starts at the chip, offset off the stub's line), and returns into column C (now allowed through the B/C gap). Each found by the starter's "routes clean" test, fixed with the router's own debug trace (`route(..., {debug:true})`), then held by fuzz on all seeds.
26. **Ask the vendor's AI, then check it against the vendor's PDFs.** AVPro Tech Sage answered in minutes what spec sheets bury (CBOX modes are exclusive; DANTE-DV2 breaks out the *source's* Dante, not the TV's; AXIS2 is PCM-only) — but with its knowledge base down it also contradicted itself (codec/latency) and got Dante's default wrong (unicast, not multicast). Rule: an AI answer is a lead; it enters the catalog only with a document behind it.

27. **One export per reader.** The quote file's contract forbids any text outside its lines; the review file is all explanation. Two files, each strict to its reader, beat one file that half-serves both. The review file carries the machine truth (the job JSON) *and* the human reading — and when a Markdown file holds several fences, import takes the **last** ```json block (an intro sentence that merely mentions a json fence once broke the round trip).

28. **Grouping is a view over the existing cluster machinery.** "Outdoor separate" didn't need new layout code: outdoor zones get a synthetic area (`__outdoor`, with `__indoor` for the rest when the job has no areas) and ride the area-cluster path the router already knew. Type grouping is a stable sort inside each cluster's TV band and speaker band. The new layouts found one old router bug straight away (a zone-east wire's lane at chip height ran through its own target chip, which was exempt from blocking so it could land) — the target is now exempt for the landing leg only. Adding the variant to the fuzz loop is what caught it.

29. **A page is a view of an advisor result, not its own calculation.** The port plan and the outlet budget depend on each other (PoE decides outlets) and on the catalog (port counts) — computing them once in `advise()` and printing, exporting and warning from that object means the sheet can never disagree with the advisor line above it. Also: when splicing a file by string search, anchor on text that occurs once (a repeated section comment duplicated a page renderer here).

30. **Research wattage per figure type, not per product.** Datasheets mix "max", "typical", "1/8 power", fuse ratings and adapter ratings under one "power" label; a PoE switch's max includes the whole PoE budget. Storing which figure is which (typical vs max vs no-PoE) is what makes the circuit sum honest — and a missing figure prints "?" with a "load is a floor" note instead of a silent zero.

31. **"Legal" is not "good" — measure the thing you actually want.** Every router guard checked legality, so a wire that toured the sheet edge passed for months. A small independent oracle (what's the best legal route here?) found the pattern in minutes; ceilings then keep it found. And greedy per-wire optimisation can hurt the whole sheet — accept a change only when the corpus totals improve.

32. **When a fix is "route them again in a different order", check what else the re-route grabs.** Re-routing a twisted pair freed the first wire's riser, and the second wire took it — a new crossing. The minimal move (swap just the two lanes, or the two risers) fixed what was actually wrong and nothing else.

47. **Count the power bricks that aren't boxes.** The outlet budget walked rack devices and rack-side encoders, but an HDBaseT balun is a companion that *serves a TV*, so its power supply fell through — the residence needed 12 outlets, not 10, which moves the WattBox pick from the 12-outlet to the 18-outlet unit. The AVPro kit ships one 48V PSU that powers both ends over the cable (PoH); put it at the rack TX so it lands on the WattBox and can be power-cycled remotely. Any companion kind with its own brick needs the same question asked: which end is it plugged in at?

48. **Read the DIP switches, not the product page.** The eARC extender kit's page says it delivers eARC "to an AVR" — true, but its receiver-end HDMI defaults to eARC OUT mode, which means it pretends to be a TV and wants the receiver's eARC *output*, the very jack the HDBaseT video already uses. Only the manual (p15, RX DIP 2) shows the second mode: a plain audio-only HDMI out into any receiver input. That one switch decides which jack it lands on, the input budget it counts against, and the install note. It was modelled as a flag on the TV's audio-return wire (`earcKit`), not a new adapter chip, so the drawing, router and validator needed no changes — only the places that name cables, jacks, parts and power learned about it.

49. **Keep distance rough on purpose.** A Bullet Train's length decides two things — its SKU and whether eARC survives (only up to 10 m) — so the app needed *some* distance, but Ryan's call was that footage belongs to another stage. Three words (Short / Average / Far) with an optional exact-feet override is enough to size the part and pick the audio-back rule, and never pretends to be a survey. It lives on the zone (`reach`, `runFt`), not the connection, because a guest pool house is far no matter what feeds it. The Bullet Train itself is a flag on the video edge (`run: "bullet"`), not an adapter chip: a cable with no box has nothing to draw.

50. **Add fuzz features on a second random stream.** The seeded random jobs are shared with the route audit, whose ceilings were tuned on exactly those jobs. Drawing the new features (distance, Bullet Train, eARC kits) from the same stream would have reshuffled every job and invalidated the baselines; a second generator seeded from the first (`SEED ^ const`) layers them on top and leaves the base jobs bit-identical — the audit and the page-width test didn't move. The fallback metric roughly doubled on the richer jobs, and the tally showed why: mostly plain optical returns crowded out by the extra receiver→TV wires, i.e. capacity, not a new routing bug. Tally *which* wires fall back before assuming either way.

51. **Checks that need a measurement stay quiet without one.** Distance defaults to Average for sizing a Bullet Train, but the length checks (copper HDMI, balun, Cat6, Toslink) only run when someone actually set the room's distance — otherwise every legacy direct run would light up on a guess.

52. **Mock the look by hand, then make the router find it.** The trunk idea was settled on a hand-laid mockup over the app's own Harlow sheet (same boxes, only the wires redrawn) with measured numbers — 102 → 22 crossings, wire length −3% — so the build had a target, not a vibe. The router pass (4T) reproduces the mockup's structure rather than its coordinates: riser per family in the rack corridor, stacked buses in each row's strip, per-cluster express runs and gutter risers, on-ramps, breakouts. Everything else it needed already existed: the lane registry, `alloc`, `pathBlocked`, `pathRegisterable` and the harness idea that a shared run is ONE net (so the registry and the hop pass treat a trunk as one conductor and it is legal by construction). Anything the trunk can't carry legally is left to the classic passes — a safety net, not a failure.

53. **Count what the eye counts.** The router's own crossing count is per wire pair, so a ×5 bundle crossing a ×7 bundle scores 35; trunks looked *worse* (102 → 133) by that metric while the sheet read far cleaner. Measuring visible crossing points (deduplicated by position) and ink (shared runs counted once) told the truth: 102 → 55, ink −38%. Pick the metric the reader experiences before judging a drawing change.

54. **A shared key needs every writer to share the move.** The harness made a bundle legal by construction — one net, one conductor — but that is a promise every later pass has to keep: the untwist passes were written before bundles existed and treated a wire as the unit, not its net. The fuzz check that would have caught it was turned off for the classic router as a "known bug"; switching it on and bisecting with a per-pass overlap probe put all 279 first-overlaps in one pass (4d) within minutes. A disabled invariant is a bug report nobody is reading.

55. **Corridor order decides the rack crossings.** Folding the rack's network and Dante patches into trunks first made Harlow *worse* (55 → 68): the network riser landed right of the Dante riser, so the Dante switch's on-ramps had to cut across the Dante branches heading into the same amps at nearly the same heights — the lane registry refused them and they fell back. Giving each family a side of the corridor (network beside its switches, feeds coming in beside their targets, video between — the mockup's order) took it to 37. Two smaller rules mattered: try several jack heights, not the one closest to the middle; and a box under its own switch (a CBOX) gets a local staple through the gap between them, not a trip out to the riser and back.

56. **A second rack is a second set of trunks, not a harder puzzle.** Keying each trunk family by its rack (`out:speaker@rack-pool`) was nearly the whole change; the lane allocator already keeps two racks' risers apart in the shared column gaps. The bugs were in assumptions: express levels scanned from the *first* rack's top, so the pool rack's feeds climbed into the gap between racks before heading east. Choosing the level by what it crosses (then by nearness to the family's own jacks) sent them under the Kitchen and Office cards instead — and the level check has to cover the riser's extension to that level too, or a trunk "finds" a level its riser can only reach through a decoder chip. The random generator's extras stream grew two-rack jobs (79 of 325) so this is tested beyond one fixture.

57. **Group rack patches by where they start.** Folding the rack's video and audio patches into one family per signal made them 142% longer: the family's riser went beside its *rightmost* source column, so a column-A source feeding the column-B matrix travelled out past column B and looped back into the matrix's left edge. Keying each patch family by its source column (`patch:video#A`) puts a riser in every gap that has sources, and the col-A patches land straight across. The per-wire breakdown (length by class, trunk vs classic) found it in one run; the totals only said "+4%". Rack patches also try several landing heights on the target, not just the one nearest the source jack — a clamped corner port is often the one lane that's taken.

58. **Draw the cable, label the subscription.** A Dante "wire" is a routing-table entry on a network whose cables are already on the sheet and the Wire Schedule; a dashed line for each subscription drew the same cable twice and paid for it in crossings (Harlow's five Dante lines alone were 15 of 32 trunk-mode crossings). Labels carry the same information where a tech reads it — at the receiving box, listing its sources, and at each source, naming its destination — so the drawing keeps the physical runs and the notes keep the logical ones. It's a per-job choice, not the default, because a dashed line still reads faster when a job has one or two Dante links.

59. **When a new mode becomes the default, re-point the old guards, don't delete them.** Making trunks the default flipped what `place()` / `route()` draw for every caller. The classic router's regression suite (hop ceilings, route audit, reroutes, fixtures) still guards the "Off" choice, so tests.html pins it explicitly with thin wrappers (`place = (…) => enginePlace(…, { trunks: false, …o })`) and the trunk tests ask for trunks by name; the fuzz run's plain variant now draws what users see (trunks) with a separate explicit classic variant for the reroute and fallback checks. Flipping the default also exposed a UI assumption: tap-to-select looked up each wire's drawn `path.wire`, which trunk mode had replaced with shared pieces — so every trunk wire now keeps an invisible path of its own that selection lights up.

60. **Walk a real job after a big default flips.** Right after trunks became the default, one Savant whole-home job built through quick-add (Atmos theater + far pool house + short den, three Bullet Trains, an eARC kit) found five things no test had: a receiver's TV sliding to HDMI OUT 2 once the eARC kit freed it from needing eARC; the Audio Setup sheet only counting separate return wires, so two TVs whose sound comes back up their Bullet Train were never told to turn eARC/ARC on; a surround room whose TV bypasses its receiver with no audio back (its apps never reach the surround speakers) — and a Savant input module with nothing plugged into it — both silent; and two labels fighting for the same short drop. One suspected bug (Enter doesn't add rooms) was the test tool's key name, not the app — check the handler before filing. The job is now a fixture.

61. **Encode the house practice, then let the budgets tell the truth.** Quick-add's "avr" room used to chain matrix → receiver → TV. Synergy's practice is separate feeds — a matrix output to the TV and another to the receiver — because HDMI pass-through through a receiver is fragile. Encoding that doubled matrix outputs per receiver room, so the walkthrough job immediately ran its 8×8 out of outputs (6 TVs + 4 receivers), and the existing output budget and no-port notes said so without new code. The same change exposed the next real conflict on its own: the AC-MX-88 can't downmix, so feeding its audio outs into the analog input module forces the sources to stereo — and the receivers with them (the downres-surround note). Defaults that follow the trade's practice make the advisor's existing checks meaningful.

62. **A box with two outputs on one face is a layout fact, not a router trick.** The AVDM encoder sends video to the switch and audio to the Savant input module from the same small chip. Classic routing gave every chip one exit point, so the second wire landed on the first and fell back; then, given two jacks, it ran out of lanes because the A|B gap was sized from wire counts without subtracting the chips parked in it; then the three audio drops crossed each other until the lanes nested topmost-outermost. Each fix was one rule (two jacks; widen the gap by a chip only when a chip has two outputs, so no other sheet moved; nest descending drops), and the input-order test was sharpened to the thing it guards — crossings between feeds into the same box — rather than any hop at all.

63. **Two lists of the same parts drift unless one function names them.** The PlanQueue export had learned AVDM encoders, the RNE-only balun and Bullet Train lengths; the takeoff page still printed "HDBaseT balun" and left the Bullet Trains and eARC kits off entirely. Both now ask `companionSku()` (and `bulletFor()`) — the export lost its private copy of the SKU rules — and a test holds the takeoff to the same parts.

64. **When the corridor matters more than the lane, try every corridor.** Links between racks used to route first (pass 3) as one fixed shape — a staple down beside the switch column — and the Estate's switch uplink crossed four wires doing it; a second rack's sources reached the matrix as four separate staircases. They now route after every room trunk (pass 4T, `linkFam`): each family of links (`link:<signal>`) is routed in full on a riser in each candidate corridor (three x's in each column gap, the east corridor and the west margin), scored by crossings then length, **rolled back** (wires, lane registry and port bookings restored), and only the cheapest is kept. Trial-and-undo is affordable here because a link family is small; it is what lets a riser choice see the sheet it will actually cross. Two-rack jobs: 1,204 → 1,165 visible crossings, fallbacks 7 → 3; the Estate total is unchanged (15) — any route from one stacked rack to the other has to cut the wires running between them.

65. **Count what's on the wire, not how many wires.** A Savant output module → amp connection is one edge carrying N analog runs (`trunkCount`). It was kept off the trunks because the trunk drawing counted *wires* per shared piece, which would have printed ×1 over six cables. The fix was in the drawing, not the router: each trunk member carries `runs`, a piece's count is the sum of its members' runs (bundle weight and ×N), Ribbon gives a member one lane per run, and a multi-run wire with no tick on its own stretch gets one. Then `rackPatchFam` / `linkFam` dropped their `trunkCount === 1` guard. 168 of 169 multi-run lines in the random jobs now ride trunks, with crossings and length level.

66. **A greedy router's first answer is a draft; rip it up.** Trunk families route one after another, so each chose its riser and bus seeing only the families before it — the residence's audio return took the gap left of the input module and every column-A patch routed earlier crossed it (11 crossings vs 5 classic). Pass 4T's family body became `routeFam(F, cfg)` (`cfg`: riser `range` / `want`, `busFar`), recording every port it books; after all families and the inter-rack links are down, each family is ripped up (its wires, its lane-registry entries by net, its ports, its `done` marks) and re-tried in each corridor at three riser positions, plus the other bus stacking, scored by the crossing *points* it makes with the rest of the sheet ×100 plus length/10 (one crossing ≈ 1,000 px — at /50 Harlow's wire length grew 33% chasing single crossings). The default is a candidate and the kept route is re-scored, so no family gets worse. An `in` family gained a rack end via the gap beside its target, so a west-margin riser can still land on the input edge. Cost: routing went from ~15 ms to ~135 ms on the stress sheet; a `WeakMap` segment cache with bounding-box rejection in `countCrossings` and one pass (a second bought 2,597 → 2,536 for twice the time) keep it interactive. Links route before the rip-up and stay put — ripping first stole the corridors four links needed.

67. **A ribbon is a layout problem, not a stroke style.** The first ribbon offset each *elementary piece* of a trunk on its own: lanes re-centred wherever a wire joined or left, corners didn't meet (the horizontal and vertical pieces offset independently), and jack stubs stair-stepped into the riser. `ribbonLayout(members)` now works per **run** — the stretches of one direction that overlap on a line — and gives each wire one lane for the whole run, ordered by where it peels off at either end (`side` + turn position, the turn position read from the *neighbouring* run's lane, iterated 6× so corners come out concentric), then draws each wire as one offset polyline (vertex = corner + both runs' offsets). Rules that came out of measuring 300+ ribbons (diagonals, ends off their jack, lanes sharing a line): a single wire is pinned to its jack at both ends; runs of the same trunk on parallel tracks ≤ 10 px apart (or whose bands would touch) merge — but never a run holding a jack stub or room drop, and exact-line runs merge first so a stub can't be dragged in transitively; wires out of one jack stay one line until the next turn (a fork); end-to-end touching stretches of two wires share a run (an on-ramp and a breakout at the same riser). Width: 10 lanes at 4 px, squeezed to 3 px for up to 13 (2.4 px blurred to a pale band on screen); fuller stretches become a 5.2 px bar with ×N that the lanes converge into. Lane crossings *inside* a ribbon are the inversions between an amp's output order and its rooms' order — they can't be removed by re-ordering a run, only moved; the layout puts them at the short fan-in, not the bus.

68. **Fix the order on the side you're allowed to move.** Lanes inside a ribbon swap when an amp's jack order (top to bottom on the riser) disagrees with its rooms' order (left to right on the bus): zero swaps needs rooms sorted by jack height. Ordering rooms by their feed's *drawn* jack height (a placement probe) changed nothing — rooms already followed their amps within each band group, and the swaps came from the band rule itself (surround rooms first), which is Ryan's and stays. So the amps move instead: in trunk mode the col-C stack sorts by the first room (in final band order) each amp feeds. Measured: Harlow lane swaps 20 → 16, 120 random jobs 1,037 → 984, sheet crossings level (Harlow 30 → 31, so its cap moved). What remains is structural: a receiver lives in col B and can't join the amp stack, and the Dante trunk *into* the amps wants the opposite stack order from the speaker trunk *out* of them — one order serves the trunk that fans out (speakers). Only the schematic's column moves; the Rack page elevation reads the job.

69. **Branch and bound costs nothing in quality when the cost is monotone.** A rip-up trial's cost — crossing points ×100 + length/10, + 1e5 per member it can't place — only grows as members commit, so each trial carries the best cost so far as `bound` and stops the moment its running tally reaches it (`crossPointsInto`, shared with `famCost`). A stopped trial could never have won, so the drawing is identical (checked: 408 routes, byte-for-byte) while routing time fell ~45% — stress 124 → 81 ms, Harlow 58 → 29, residence 32 → 14. The headroom tempted a second rip-up pass (−3% crossings) but it doubled the stress sheet again; live editing wins.

70. **Dogfood the starter you ship.** Building Ryan's usual system (MXNet + Savant starter, ten rooms by quick-add) and reading every sheet found four things no metric had: (1) quick-add appends receivers to the rack list, so in col B they stacked *between* the Savant output module and the MDX-16 it feeds — the ×6 patch looped round all three; amp-feeding boxes now sink to the bottom of their column in trunk mode (stress 56 → 51 crossings, Harlow lane swaps 16 → 10); (2) a network line ran through a source tile's caption — captions are obstacles now, in trunk mode only (the classic router lost 3 routes to them); (3) in Ribbon, a speaker riser ending right under the theater's decoder reserved its whole band there and walled off the video drop — row drops gained off-centre chip landings and doglegs, and a **repair pass** re-routes a stuck family after moving the family whose lanes blocked it (`blockingNet`, then the rest, bounded, 24 trials per route; families whose failures had no candidate at all are structural and skipped) — Ribbon fallbacks on 325 random jobs 23 → 13, Bundle 7 → 5; (4) the repair can starve a wire the classic passes route later (fuzz #244: a return vanished), so `route()` re-routes with `noRepair` when a repaired sheet has an unrouted wire and keeps the better. The dogfood job is now `test-fixtures/dogfood-mxnet-savant.json`. (5) a riser climbing out of the rack cut the rack's title — as an obstacle it cost 5 → 15 fallbacks (risers legitimately leave through the rack's top-left), so the title is instead drawn again over the wiring with a white halo.

71. **Place labels last, against everything drawn.** Trunk wire numbers sat at the midpoint of the wire's *centre-line* room-end stretch — in Ribbon the lanes are elsewhere, and nothing checked what was under the text (a ribbon, the theater card's dashed border). `drawTrunks` now queues label requests and places them after every net is drawn: spots along the last four stretches of the wire's *drawn* line (its ribbon lane), both sides, scored by other labels (×100), room cards / chips / rack boxes (×30), drawn segments of every wire (×10), then distance from the room. A test parses the rendered `wirenum` texts on Harlow and the dogfood job in both styles and fails on any label touching another, a card or a chip. Catalog heights a dealer should still confirm carry `rackUnits` + `rackUnitsConfirm: true` (Savant PAV-AIM7C-20 / PAV-AOM8C at 1U, Ryan 2026-10-01): drawn at that height, listed in the advisor's "needs to be confirmed" note.

72. **An editor for data the engine reads is mostly a vocabulary.** The catalog had 61 flags; only ~17 change what the app does (grep each one across `app/*.js` and index.html before deciding which deserve a checkbox). `app/library.js` holds the editor's vocabulary — `LIB_TYPES`, `SIGNALS`, `TYPE_IO` (which connectors a type shows; an entry's own non-zero counts always show), `LIB_SECTIONS` (fields per type), `BEHAVIOURS` (flag → plain label + what it changes) — plus the pure operations (`duplicateDevice`, `newId`, `checkEntry`, `exportLibrary` / `planImport` / `applyImport`), all unit-tested; index.html only draws it. Two rules made it safe: a copy is `custom: true`, unverified and part-number-less (the PlanQueue export marks it), and the existing shipped-catalog sync (`catalogBase` / `CAT_STALE`) already gave "edited shipped entry" its meaning, so Revert is `takeShipped`. Rebuilding a stale jack list is just deleting `ports`: ports.js derives one from the counts for any entry without an audited list. The import runs through `stripUnsafe`.

73. **Store a kit's rooms as the language that makes them.** A starter kit could have stored its zones as data, but their wiring (decoders, receivers, eARC returns) would have had to be re-targeted to the new job's rack ids. Instead `zoneToQuick` (quickadd.js) writes each room back as quick-add text and a new job re-adds it through `planCommands` → `autoHookup`, which already knows how to wire a room to whatever rack is there (it reused the kit's three receivers rather than adding three more). Two traps found by round-tripping the dogfood job: "avr" in quick-add means the receiver *feeds the TV* (the pass-through option), so a surround room on Synergy's separate-feeds default must be written "matrix"; and a brand with no size must not be followed by "tv" (the parser leaves the word in the room name). Tests round-trip the dogfood job (same rooms, same TV feeds, same rack) and seven phrases through parse → write → parse. Kits live in `SETTINGS.starters` {mine, order, hidden}; shipped kits stay in starters.js and `listStarters` merges them.

74. **A starter kit is a test fixture you ship.** Drafting seven kits and building each with its rooms found five things the random jobs never had: (1) the "nothing plugged in" check fired on Sonos Amps, which stream their own music; (2) a prewire-only job errored on every unfed room — a pre-wire room is fine with no rack gear yet (a warning once there is gear to home-run to), a future one always; (3) an encoder chip 18 px from its switch had no riser candidate (`b.x - chipR >= 20`) and fell back — the threshold is 10 now, and a chip link tries several landing heights like a return; (4) one small source tile with two outgoing wires runs out of exit heights in the Off drawing — the outdoor kit uses a Sonos Port per amp; (5) a projector was given an eARC-kit return — projectors now get no audio return at all. Quick-add fills amps in rack order, so the outdoor kit lists its landscape rooms first to land them on the Sonance. Every kit's rooms are validated and routed in all three styles by a test.
75. **A new feature is only as reachable as the oldest door into it.** The device library let you copy an MDX-16 into an MDX-18, but GEAR's "＋ Add device" was still a `prompt()` that made an unlinked *source* box — so the new product took three more steps (rename, pick product, fix the type) to reach a job. Add device now opens the library as a picker. Walk the path a new thing takes into a job, not just the screen that makes it.
76. **Color that means something has to reuse the meaning already on the page.** The wires already said red = video, blue = audio, green = network, so the box colors were derived from them (a receiver, video + audio, is purple; MXNet, video over a network, magenta; AVB, audio over a network, teal) instead of a second palette competing with the first. Tints stay dark enough that the rack still reads as black gear; the edge carries the hue. Key the kind on capability (the MXNet flag), not the stored type, or legacy entries filed under the wrong type come out the wrong color.
77. **A status light should reuse the advisor's count, never recount.** `boxUsage(job, ix, catalog, advice)` reads switch ports off the port plan and outlets off the power plan, so the lit windows can't disagree with the "ports full" or "outlets short" notes; the renderer only draws what it's handed (`opts.usage`). Two things only showed up in a rendered kit: two WattBoxes filled first-come read as one maxed-out unit (split by size instead), and the amp's B&W "used" color was near-black on a black amp, invisible since grayscale shipped. Kit-built sources had no faces at all — faces keyed on `sourceType`, which only hand-made fixtures set — so the face now falls back to the name.
78. **A size change is a routing change — measure it per drawing style before shipping it.** Growing the TV and speaker glyphs 25% (`GLYPH_SCALES`, chosen in `place()`: the biggest that costs the sheet ≤ 3% of its fit scale) looked cosmetic, but on 200 random jobs it moved best-effort wires 2 → 1 in Bundle, 5 → 4 in Ribbon and 11 → 16 in Off, where gutter feeds squeeze past taller cards. So Off stays at 1×; the guard test compares Bundle fallbacks at 1× and at the chosen scale on 60 jobs. A second try (2026-10-02) gave Off a 1.12× step: 1.12× alone held 11 best-effort wires, but picking the size per job gave 15 — Off's per-wire gutter routing is so sensitive to card sizes that *which* jobs fail reshuffles with any change. Bigger icons in Off need Off's feed routing reworked first; a fixed-scale sample can't prove a per-job choice.
79. **Scan every label against every body, on every kit, before calling labels done.** The trunk counts (×N) went at the middle of the longest shared run; a scan of 481 counts over the kits, fixtures and 60 random jobs found 11 sitting on a box, chip or another count — all Bundle, the default. `tickAt` now slides along the run, tries its other side, then other stretches carrying the same wires (a two-run line squeezed into a 10 px gap between two boxes put its ×2 on its free riser). 0 of 481 now; a test holds it. Same session, a rejected idea worth keeping: sizing the top corridor by trunks instead of wires printed 1–2.6% bigger but cost 1–2% more crossings — the spare lanes are what the rip-up pass untangles with, so they stayed.
80. **Walk new screens at phone width with the keyboard in mind.** The 2026-10-01 tablet/phone pass found the library, kit manager and add-device picker sound (full-screen overlays, 44 px targets, no sideways scroll) but one real snag: on a phone the product list is ~4 rows over the editor, so search is how you pick — and a search that filtered the open product out left its editor showing. A filtered-out selection now opens the first match.
81. **Split a drawing by cutting the job, not the renderer.** "A sheet per rack" (`app/sheets.js`) never touches place/route/render: `sheetGroups` decides which rack and rooms each sheet owns (area home rack first, then the rack whose gear feeds the room), and `sheetJob` returns an ordinary job per sheet — its racks whole, the other racks cut down to the boxes wired straight to it and renamed "— sheet N", connections kept only when both ends are on the sheet, other solutions untouched so indexes line up. Validation, lights and the advisor keep reading the whole job. The test that matters is conservation: on random two-rack jobs every room lands on exactly one sheet and every wire on at least one.
82. **No pricing, ever — enforced, not remembered.** The repo is public (it is the GitHub Pages site), so SignalPath carries no prices of any kind: not PlanQueue's sell prices (which never came in), and not the public list prices, subscription fees and driver-budget figures that had crept into catalog notes either (removed 2026-10-02). Two guards hold the rule: `check-public.py` runs inside `deploy.sh` on the exact copy about to be committed and stops the deploy on any money amount, "/mo"-style fee, price field or PlanQueue-export fingerprint; and a test scans the catalog and every shipped module the same way. A schematic doesn't need prices — Synergy prices in PlanQueue.
83. **Fuzz the gate, not just the engine.** The random-job fuzz only ever makes well-formed jobs, so it never asks what a hand-edited or half-corrupted file does after `assertJobShape` lets it in. A 2026-10-02 hardening pass (`harden/` in the source folder: wide coverage of every feature together, 3,000-mutant runs over many seeds, junk library files and kit stores, a redraw timer) mutated real jobs — fields deleted, wrong types, dangling refs, huge numbers — pushed each through the app's own import gate and the whole pipeline, and found 11 bugs the 855 tests never had: a number where text belongs (`config: 12`, `stage: 1`, an area named 7) threw at the first `.startsWith`; `platforms`/`revisions` as text; a revision field holding an object printed "[object Object]"; a one-word `confirm`; a file without the SignalPath marker passed the gate but failed at load (so it saved, then never drew); a library file with `devices: null` (null is an object); and a damaged kit store broke the New Job picker. All fixed where every job passes — `normalizeJob` coerces text fields and repairs lists, `tidyStarterStore` repairs the kit store at boot, import and listing — each with a regression test. Also verified the same day: script-injection names in every field render as text on every screen, sheet tab and the print packet; every kit walks clean through all styles, toggles, exports and print; full redraw ≤ 33 ms on normal jobs, ~120 ms on the 25-room stress job. Storage blocked (a private window, site data off) was then simulated by a test copy of the page that makes localStorage, sessionStorage and IndexedDB throw before the app's code runs: everything worked on the in-memory fallback — new job from a kit, library edits, saving a kit, every toggle — but silently, so a whole job could vanish with the tab. Now a bar says the browser isn't letting SignalPath save and offers "Save a job file now".
84. **Two outputs that count the same thing must agree — check them against each other.** The takeoff page and the PlanQueue import both list the job's gear, but each walked the job its own way: the export added rack-side adapters only when they were encoders, so an MXNet decoder feeding a receiver or amp in the rack (or a 10G transceiver doing that job) dropped off the quote while the takeoff counted it — the demo estate quoted 3 decoders of 5, the 10G estate kit 9 transceivers of 12. 855 tests and the random fuzz missed it because the random jobs never put a decoder on rack gear; the cross-check (`harden/pq-adapters.mjs`: every adapter in the job, by SKU, quoted exactly once) only caught it once the demo jobs and starter kits joined the pool. Run a new check against the old code too — if it passes there, it isn't testing the bug.

## 10. Order of construction (what to build when)

1. Data model + `loadJob`/`indexJob` + first fixtures — get tests running the same day.
2. `validate`, then a minimal `place` + `render` (boxes and labels, no wires) — something on screen fast.
3. Router v1 (stubs + simple channels), then iterate against fixtures with hop-count guards.
4. Editor shell + autosave; wire `refresh()` end to end.
5. Catalog + `advise` + Settings; then importers; then print pages.
6. Polish rounds driven by user redlines: glyphs, interactivity, trunk runs, overrides, returns, grayscale, remotes — each round = feature + tests + deploy + memory note.

The single habit that made the project work: **every round ends with all tests green, a deploy, and a written record.** Nothing was ever "done" in the working tree only.

32. **Harden by feeding the whole pipeline bad input, then fix at the one door.** A scratch harness ran every sample and 100+ random jobs through load → advise → every page → every export under a dozen mutations (typo'd numbers, "?" figures, missing lists, unknown types, hostile names, wrong-type fields, old-format jobs) and grepped the output for `NaN` / `undefined` / `[object Object]`. What it found was one class of bug each, so each fix lives in one place: `normalizeJob()` in `loadJob` (missing lists → empty, holes dropped, unnamed zone/rack named, object-in-a-text-field dropped); `specNum()`/`SPEC_LIMITS` in `specFor` (a typed figure is a number in range or it's unknown — `"?"` once became `NaN`-tall rack boxes); `tidySurvey()` at the AVWalk/Blueprinted door (text fields must be text, lists must be lists); `route()` reports a wire to an endpoint it drew no slot for instead of throwing. Clamp anything a loop runs on: a 6500" TV typo drew a 10,000-unit card and ran the tab out of memory; a "1-10000000" channel range and a 10-million source count would have done the same. Saved jobs that aren't jobs are skipped at read (`dbAll`), never deleted.

33. **Plan both ends of a fan-in, not just the fan-out.** Output ports were planned (farthest destination → top port) but inputs were first-come: an encoder routed early took whatever port was free, so a cable box landed above Apple TV 2 and cost a hop. Now, before pass 3, every feed arriving at a device's LEFT edge from the west is planned: its port is chosen in source-height order (`leftPlan`), and its riser (the jog in the channel) gets a rank per column — rising wires lowest-landing nearest the column, dropping ones highest-landing — the only orders in which a pair nests. Ranks are enforced as a *range*: bounded by the nearest placed rank on each side, minus a lane for every rank still to come, so a wire routed early leaves room instead of boxing out a later one; a ranked riser with no legal x retries unranked (order never beats routable). Measured three variants before keeping one: ports-only helped little (twists 101→120), ports + ranked risers won everywhere (crossings −5% on 60 random jobs, twists 101→97, fallbacks unchanged, every starter 0 hops on inputs), and re-sequencing pass 3 by rank made things worse (fallbacks 5→10, a wire through a switch) — rejected.

34. **A private source can feed a public app — take the key, leave the rest.** PlanQueue's product export (1,833 lines) carries Synergy's private pricing and is marked private; SignalPath is a public GitHub Pages site. The sync took SKUs only: each catalog device was matched by hand to an exact PlanQueue SKU (58 of 89; PlanQueue's SKU column is the match key even where it's odd — Sonance SKUs are spelled-out names like "Sonamp DSP 2-750 MKIII", Ubiquiti's carry wattage like "UDM-SE (180W)", Savant's revision suffixes differ from the manufacturer's), the rest flagged `notInPlanQueue` so the export says "needs SKU" instead of guessing. A script asserted every mapped SKU exists in the export and that no field other than `partNo`/`partNoUnsure`/`notInPlanQueue` changed; a test fails if a price field ever appears in the catalog.
35. **When an outside system becomes the master for names, rename with aliases — the name is load-bearing.** Taking PlanQueue's names (MRX 540 8K → MRX 540, M4800D → ACP-DMZ-M4800D, Roku Ultra (2024) → Ultra) broke eight tests at once, because the catalog `model` is also the drawing label, the command/AI lookup key and the auto-link key. Three rules kept it safe: every renamed entry lists its old names in `aliases` (auto-link and `findProduct` read them, so a saved job's "MRX 540 8K" still links); a bare name only auto-links when it carries a model number (PlanQueue's short names — "Amp", "Ultra", "APPLE TV 4K" — would otherwise capture a generic "Amp" or "Apple TV"; brand + name still links); and where the master's own record is wrong (HYPE-PENTA's name reads HEPTA; Sonance names are bare numbers) the catalog keeps a correct name and says why in `notes`, rather than print a wrong label on paper. Two entries that are the same hardware in different roles (CBOX-HA vs its Dante-mode entry) keep distinct names: identical names make auto-link refuse both.
36. **Zoom a drawing with a CSS variable, not a re-render.** `#canvas svg { width: calc(100% * var(--zoom)) }` with the variable on `#canvas` (which `refresh()` never replaces) makes zoom survive every redraw for free; the canvas scrolls to pan. Keep the pinned point fixed by converting it to fit-width sheet units once (`(scroll + pointer − padding) / zoom`) and re-deriving scroll from it after each zoom change — the same `zoomAt()` serves buttons, ⌘-wheel (a Mac trackpad pinch arrives as `ctrlKey` + wheel) and two-finger touch (anchor taken at `touchstart`, so the pair zooms and pans together). `touch-action: pan-x pan-y` on the canvas plus `preventDefault` on Safari's `gesturestart/gesturechange` keeps the page itself from zooming. Swallow the click that iOS can deliver when two fingers lift. Tested with synthetic `Touch`/`TouchEvent`s: point drift 0.0000 at 200%.
37. **As-built = a copy that carries its own baseline.** Rather than a second solution in the same job (solutions share the House, so a room edit in the as-built would rewrite the proposal), `startAsBuilt` folds the chosen solution's overrides into a standalone job and stores the proposal inside it (`job.job.asBuilt.baseline = {house, solution}`). The diff is then a pure function of one file — it survives export/import, needs no link back to the original job, and the original is never touched. Stable ids make the diff exact: rooms/endpoints/devices/adapters by id, wires by `from→to|signal`. One numbered list feeds all three views (clouds, JOB tab, changes page) so they can't disagree; removed items are list-only because there's nothing on the sheet to cloud. The clouds are drawn by the caller (`changeMarks(changes, P, rt)`) and handed to `render()` as `opts.marks` inside the drawing-space group — no engine↔asbuilt import cycle, and they sit on top with `pointer-events="none"` so taps still reach wires. A wire is clouded around the middle of its longest leg: a whole run would cloud half the sheet. `opts.packet = "client"` trims `pageGroups` to equipment + rack and the caller skips the marks.
38. **When a format forbids notes, say it with the target's own vocabulary.** PlanQ's format sheet (2026-09-28) banned the fourth "note" field the export had leaned on ("customer supplied", "PlanQueue picks the package", "unsure"). Every one of those had an exact counterpart already in PlanQueue's catalog: Customer-Supplied items (TV / Speakers / Soundbar / Subwoofer / Equipment), Synergy's placeholders (Unspecified TV / Unspecified Speakers) and its Prewire - … items. Reading the catalog export for the manufacturer "Synergy" found them in a minute. Consequence to expect: lines that notes used to keep apart now merge (the video CBOX and the Dante-mode CBOX are both "2 | AVPro Edge | AC-MXNET-CBOX-HA") — correct for a quote, and the tests were updated to say so; a sub is kept on its own "Unspecified Speakers" line with an internal line key.
39. **Record install facts on the thing they describe, and keep them out of the diff.** Serial/MAC/IP live on the box (`d.install`), not in a side table keyed by id: a deleted box takes its record with it and a copied job carries it. `asBuiltChanges` compares a fixed field list (`DEV_FIELDS`), so adding a field to a box never shows up as a △ — the install record isn't a deviation from the proposal. Normalize at the point of entry, validate at the point of display: the MAC is rewritten to `AA:BB:CC:DD:EE:FF` on change (techs type it three ways off a label), but a bad IP is kept as typed and flagged (warning on the JOB row, shaded row on the page, a Check column in the CSV) — never silently dropped. The CSV quotes every cell and prefixes `= + - @` so a note can't run as a spreadsheet formula.
40. **A recorded fact pins; a suggestion flows around it.** Switch ports are computed (rack gear low, TVs by zone, uplinks on SFP) until a tech records the real one. Recorded ports (`sol.portMap[switch][box]`) are taken out of the free pool first, then the same suggestion algorithm fills the rest — so recording port 5 never makes another box's suggestion land on 5, and with nothing recorded the plan is byte-identical to before (a test pins that). Keep the map keyed by switch *and* box: a control box sits on two switches with two different ports. Stale entries (a box moved off that switch) are ignored rather than cleaned, so undoing a move restores its port. On screen, keep the edit list in a fixed order even though the printed table re-sorts by port — rows jumping under a finger mid-entry is worse than an unsorted form.
41. **Build real jobs through the UI, not just fixtures — the gaps live between features.** A 2026-09-29 walkthrough (a condo on the Theater starter, a Dante whole-home, a Savant new build with pre-wire, local and future rooms, then as-built) found fourteen things 600+ tests never saw, because each feature had been tested alone: quick-add's `local` created an Apple TV but never wired it (the validator's "a local source feeds its TV" exemption hid it); a powered soundbar had no hookup choice at all, and the TV→bar eARC edge was misread as an optical return (so changing "TV audio back" deleted it); a pre-wire TV got no run; `avr` rooms on a whole-home rack got a receiver with no input; a room with no gear was silently dropped while its preview chip promised it; flipping a room from pre-wire to included left its runs pre-wire; the Savant starter never said it was Savant (no licensing advice); "plug something into" defaulted to the WattBox sending HDMI into an amp; and a cable box feeding a receiver, a TV and an amp couldn't route (below). Keep `scratchpad`-style checkers that run a saved job through validate → route → geometry → pages → exports, and walk a new job end to end after any change to quick-add or hookup.
42. **A tile must be tall enough for the lanes leaving it.** The port planner spreads a box's exits evenly over its edge, clamped to the tile: three exits on a 22px source tile landed 6px apart, under the router's 9px lane clearance, so the third wire could never register a lane anywhere and fell back through the receiver. Trying more double-jog levels (the first fix attempted) changed nothing — every candidate failed on its very first segment. The fix is placement: a small tile with ≥3 exits grows to `(n−1)·12 + 16` px (capped at 4 exits) — but only when at least one exit stays in the rack. A source fanning out only to zones rides shared harness trunks, and growing it (the dense one-source fixture, 9 TV feeds) crowded the column gap a TV return climbs through and broke that route. Measured on the fuzz corpus: best-effort fallbacks 37 wires / 29 layouts → 33 / 26.
43. **Model the signal, not the rules.** Residential AV is five signal families (video, digital audio, analog line, speaker level, network) and one audio format ladder (2ch PCM < 5.1 lossy < full/Atmos); every link keeps or lowers the format, only a decoding box changes it. The advisor had grown one-off rules ("MDX digital ins are PCM-only", "AXIS2: set the TV to PCM") that each knew a fact but not what actually arrives — `audiochain.js` walks each source forward through the drawn links and asks one question at every box. Two things the port audit changed: downmixing is per OUTPUT, not per box (an AXION's AUDIO blocks always downmix while its HDMI/HDBaseT keep Atmos; an AVDM-EV2's local 5-pin downmixes but its MXNet stream doesn't), and a source's own analog out is already 2ch (a cable box downmixes it), so only HDMI carries bitstream onward. Stacked MXNet switches are one AV network (follow the Cat6 between them) or a far decoder's amp is missed.
44. **Offer only what can connect — gray the rest, with the reason.** The GEAR editor used to be a database form: a 108-item product list for an Apple TV (every product of every kind) and three independent menus per wire (From 41 × To 41 × Carries 5), most combinations physically impossible. With ports in the catalog the choice collapses to one: pick the far box and its jack together, and the signal follows from the jacks. Impossible choices stay visible but grayed with why ("every HDMI output on Cable Box is in use", "speakers only take a signal"), which teaches the rule and lets the designer see what to change; the free-form row survives as "Advanced" because every rule has exceptions. Ports are DERIVED at view time (first free compatible jack, with tech preferences), and only a hand-picked jack is stored (`fromPort` / `toPort`) — so re-wiring never leaves stale jack numbers behind, and a pin always wins. Two traps: a box's RF input (CABLE IN / SAT IN) is a "coax input" to a naive list — drop it or a coax audio out will "plug into" a cable box; and an unlinked box must use the same name-match profile the sizing code uses (`catalogFor`) or an "Apple TV" is offered an analog out it doesn't have. Walking the jacks also exposed a starter that can't be built as drawn (the Savant music server is digital-only into an analog-only input module).
45. **Restyle by rules, and keep the old controls doing the work.** The visual refresh was specified as a handful of rules (one control per kind of choice, one meaning per colour, touch-size targets, labels above) and mocked up before/after before any code. Implementation was mostly a style layer plus three small markup changes; the ~15 remaining `<select>`s were converted by one `enhanceSelects()` pass after every panel render — the select stays in the DOM, hidden, and the field button just sets its value and fires `change`, so none of the existing handlers moved. The same trick built the job button: the old job / option / stage selects and the File menu are hidden but still do the work. `:has(> label)` switches a field row to label-above without touching the ~60 `field()` call sites; the few rows that must stay inline get `.f.inline`. Advisor findings became objects (level, message, ref) instead of HTML strings — a short title is split off at the earliest " — " or ": ", and the ref drives "Go to ›".
46. **Fill the page by searching layouts, and let the router's own audit pick the family.** "Use the page width" was solved without touching the layout rules: `place()` now runs the classic placement plus a few variants (a virtual page 1.15–2.1× wider for where rows wrap — pointless to wrap at 1444 units when the drawing will print at 70% — and TV-only rooms beside the speaker rooms) and keeps the highest `fitScale`, only if ≥3% better so tuned big layouts never churn. Placement is ~1 ms, so trying eight is free. The first cut included "side by side" on its own: it printed bigger but its wires got longer (1.202× Manhattan vs 1.168) and failed the route-efficiency ceiling. Measuring each variant family against the 60-random-job audit showed the wider-wrap family routes BETTER than classic, so the final set is chosen by that data (+8.3% size, 1.165×, fallbacks 5 → 2, twists 97 → 77). The new layouts exposed one existing router habit — a <6px sideways step in the middle of a riser — now straightened in `commit()` when the slid run stays legal. Tighten the ceilings after a win so it can't quietly slip back.
